Aula 1

Integração com APIs RESTful

A aula apresenta REST como um estilo arquitetural para construir APIs de forma padronizada, com requisições independentes, recursos identificados por URLs, uso de métodos HTTP e respostas frequentemente em JSON.

1

Antes de REST: o que é uma API?

API é uma forma organizada de permitir que dois sistemas troquem informações ou utilizem funcionalidades um do outro.

Explicação técnica

O front-end envia uma requisição para um serviço. Esse serviço processa o pedido e devolve uma resposta. A API define quais caminhos, dados e regras podem ser utilizados nessa comunicação.

💡 Pense assim: o garçom

Você não entra na cozinha para preparar seu prato. Você faz o pedido ao garçom, ele leva a solicitação à cozinha e depois traz a resposta. A API faz o papel desse intermediário entre sistemas.

🌎 Onde isso aparece na vida real?Aplicativos de clima, mapas, pagamentos, envio de mensagens, login social e consulta de produtos usam integrações com serviços externos.
🖥️

Cliente

É quem solicita algo. Em nosso contexto, normalmente o navegador ou o front-end.

Analogia: a pessoa que faz o pedido.
🏢

Servidor

Recebe a requisição, processa e devolve uma resposta.

Analogia: a cozinha que prepara o pedido.
🚪

Endpoint

É um endereço específico disponibilizado pela API, como /produtos.

Analogia: uma porta para um setor específico.
🔗

URL

Identifica o recurso que queremos acessar, por exemplo /users/1.

Analogia: o endereço para encontrar o destino.
↔

Stateless

Cada requisição é independente; ela precisa trazer o necessário para ser entendida.

Analogia: cada pedido vem com suas próprias instruções.
{ }

JSON

Formato textual muito usado para organizar e transportar dados.

Analogia: uma ficha com campos e valores.
Entendendo os dados

Como ler um JSON?

JSON organiza informações em pares de chave e valor. Veja um exemplo simples de produto.

{
  "nome": "Mouse",
  "preco": 79.90,
  "disponivel": true
}

"nome" → chave que identifica a informação.

"Mouse" → valor associado à chave.

79.90 → valor numérico.

true → valor lógico.

📖 Por que a documentação de uma API é importante?

A documentação orienta como realizar a integração: quais recursos existem, quais caminhos utilizar, qual método corresponde a cada ação, quais dados enviar e que tipo de resposta esperar.

💡 Pense assim: manual de instruções

Sem o manual você pode até tentar usar um equipamento, mas perde tempo experimentando. A documentação reduz tentativas e ajuda a seguir as regras do serviço.

Aula 2

Integração com GraphQL

O material avança para GraphQL, destacando consultas eficientes, definição de esquema, tipos, consultas e relacionamentos, além da possibilidade de recuperar apenas os dados necessários.

1

Qual problema o GraphQL ajuda a resolver?

Em algumas telas, o front-end precisa de um conjunto específico de dados. GraphQL permite descrever na própria consulta quais campos devem retornar.

Explicação técnica

Em GraphQL, o cliente envia uma query descrevendo os campos desejados. A consulta é validada com base em um schema, que define os tipos de dados e as operações disponíveis.

💡 Pense assim: monte seu pedido

REST pode lembrar um combo já definido. GraphQL pode lembrar um pedido em que você seleciona exatamente os itens que deseja receber.

REST

Resposta definida pelo endpoint

GET /usuarios/1

O endpoint possui uma estrutura de resposta previamente definida pelo serviço.

GraphQL

Campos definidos na consulta

query {
  usuario {
    nome
    email
  }
}

O cliente declara quais campos deseja obter naquela consulta.

Importante: isso não significa que GraphQL seja sempre “melhor”. REST e GraphQL são abordagens diferentes e podem ser adequadas a contextos diferentes.

🔎

Query

É a consulta enviada para solicitar dados.

Analogia: a lista do que você deseja pedir.
🏗️

Schema

Descreve os tipos e operações disponíveis.

Analogia: a planta da casa mostrando o que existe.
🧩

Type

Define a estrutura de determinado conjunto de dados.

Analogia: um molde que diz quais características um objeto possui.
🔗

Relacionamento

Mostra como informações diferentes se conectam.

Exemplo: evento → palestrante → local.

🏗️ Schema como planta de uma casa

Uma planta mostra quais cômodos existem e como se conectam. No GraphQL, o schema descreve quais tipos existem, quais campos cada tipo possui e quais consultas podem ser realizadas.

type Evento {
  titulo: String
  palestrante: Palestrante
  local: Local
}

Autenticação com OAuth e JWT
A aula trabalha autenticação segura, login com conta de terceiros como Google, uso de JWT e feedback visual para tornar o processo de login mais claro para o usuário.


      

        
Autenticação
Quem é você?
É o processo de verificar a identidade de quem está tentando entrar.
💡 Escola:
mostrar sua carteirinha para confirmar sua identidade.

        
Autorização
O que você pode fazer?
Depois de saber quem é o usuário, o sistema pode controlar quais recursos ele pode acessar.
💡 Escola:
saber quais salas e sistemas aquele usuário tem permissão para acessar.

      


      

        
1
OAuth: autenticação com um serviço confiável
No material, Google aparece como exemplo de conta de terceiros utilizada para login.

        
Explicação simples
Em vez de criar uma nova conta e senha em cada aplicação, o usuário pode utilizar um provedor conhecido para realizar o processo de autenticação.
A aplicação não precisa “receber a senha do Google” para usar o fluxo OAuth. O processo ocorre por redirecionamentos e tokens controlados pelo provedor.
💡 Pense assim: uma credencial confiável
É como apresentar uma credencial emitida por uma instituição reconhecida. A aplicação confia no processo realizado pelo provedor e recebe uma resposta de autenticação.

      


      
Conceito da atividade
client_id: quem está pedindo o login?
Na análise proposta no roteiro, o aluno precisa identificar a finalidade do client_id. Ele representa a aplicação cadastrada no provedor OAuth e ajuda o serviço a reconhecer quem está solicitando o fluxo de autenticação.
💡 Pense assim: o crachá da aplicação
Quando a aplicação chega ao “balcão” do Google para iniciar o login, ela precisa se identificar. O client_id funciona como esse identificador.

JWT: como a aplicação reconhece uma sessão autenticada?
O roteiro pede que o estudante explique o propósito do JWT gerado pelo back-end depois da validação do token do Google.

        
JWT é um formato de token compacto. Em um fluxo de autenticação, ele pode ser usado pelo back-end para representar informações da sessão e permitir que requisições posteriores sejam reconhecidas como autenticadas.
Importante: token não deve ser tratado como se fosse uma senha comum nem exposto sem necessidade.
💡 Pense assim: pulseira de um evento
Depois que sua entrada é validada, você recebe uma pulseira. Em áreas autorizadas, ela serve como sinal de que você já passou pela verificação.

      


      
Visualização conceitual
JWT em três partes
HEADER.PAYLOAD.SIGNATURE
Header
Metadados sobre o token e seu formato.
Payload
Informações/claims transportadas no token.
Signature
Parte utilizada para verificar integridade/autenticidade.
Demonstração didática. Não cole tokens reais nesta página.

Prática guiada
Laboratório Front-End
Agora os conceitos aparecem em pequenos trechos de código. A ideia é entender o papel de cada linha antes de pensar em programas maiores.

      

        
REST
Consumindo um recurso
fetch('/api/produtos')
  .then(resposta => resposta.json())
  .then(dados => console.log(dados));
fetch() inicia a requisição.
resposta.json() interpreta o corpo como JSON.
O segundo .then() trabalha com os dados recebidos.
💡 Analogia:
você faz um pedido e combina o que fará quando a entrega chegar.

        
UX
Estado de carregamento
setLoading(true);
// aguarda a operação
setLoading(false);
true indica que a operação começou.
false indica que ela terminou.
💡 Analogia:
acender e apagar a placa “atendimento em andamento”.

        
Erro
Feedback para o usuário
setError(
  'Erro na autenticação. Tente novamente.'
);
O estado guarda uma mensagem que pode ser exibida na interface.
O objetivo é orientar o usuário em vez de deixá-lo sem resposta.

        
Token
Exemplo de armazenamento local
localStorage.setItem('token', jwt);
Este é apenas um exemplo didático ligado à pergunta do roteiro sobre armazenamento e uso do JWT no front-end.
Em aplicações reais, decisões de armazenamento exigem análise de segurança do projeto.
